Compact forms

Every component below is written in its shortest equivalent form. Compare with examples/report.html to see the BEM-style longer markup.

Skeleton

The document above uses the minimal skeleton: no <head> wrapper, no data-theme default, and a bare <main> directly inside <body class="bx">. The framework's reading-column rules apply to either .bx-doc or .bx > main.

Callouts via <aside data-tone>

The semantic form replaces a 4-class div with one attribute. Six tones recognized.

Info

The shortest callout is <aside data-tone="info">…</aside>. The icon and accent color come from the tone.

Note

Tones available: info, note, tip, success, warn, danger.

Tip

The BEM form (class="bx-callout bx-callout--tip") still works for back-compat.

Success

All six tones render identically to the class-based form.

Warn

If you combine data-tone with class="bx-related", behavior is undefined — pick one.

Danger

Don't use data-tone on a generic <aside> that isn't meant to be a callout — the styling applies to any aside[data-tone] inside .bx.

Cards via bare <article>

Inside .bx-grid, any <article> picks up card styling. <section> is intentionally excluded so markdown islands can sit inside grids.

Markdown islands

This region is written as Markdown inside <section data-md>. Paragraphs, headings, lists, inline code, and emphasis all stay in Markdown — far denser than the equivalent HTML.

### Findings The redesign cut **first-screen abandonment** by *14 percentage points*. Three reasons stood out: - One-screen flow removed the back-button anti-pattern that confused 8 of 14 interviewees. - The new default for the `notification_channel` field matched what most users expected. - Step labels were shortened — `Enable team sharing` → `Share`. Open questions: 1. Does the win hold for cohorts with `team_size > 50`? 2. Are completion times also improving, or are we trading one metric for another? 3. Can the same screen-compression idea apply to the import flow?

What this saves vs the long form

Each component in this document is one to a few tokens shorter than its BEM-style equivalent. The markdown island is the dominant saving — it replaces several paragraphs, a list, and headings worth of HTML markup with their Markdown shapes (roughly half the tokens for that region).

When to use the longer forms

Pick the BEM-style class when you need to apply multiple bento patterns to one element, when integrating with a non-bento parent that uses <aside> for layout, or when style-overriding via specific selectors.
