OVERVIEW bento v0.1

bento スキルの全体像

bento は AI 出力を「読まれる HTML」に変える skill です。 視覚は CDN ホストの CSS/JS が、文は writing-style.md が、 文書構造は readability.md が担保し、双方向 UI 用のプリミティブも揃っています。 6 分で全体像を掴めるよう、各層を要点だけまとめました。

三層 + 双方向プリミティブ 2026-05-12 Reading time: 6 min

最初に結論

三原則

視覚は自動 / 文は規律 / 文書は skimmer 優先。 この三つさえ守れば、bento は同じトークン量で 「読まれる前に閉じられる」HTML を「最後まで読まれる」HTML に変えます。

Markdown は読みやすく、トークンも安いのですが、表現の天井が低い。 HTML はリッチですが手書きするとトークンが嵩む。 bento はこの両方の弱点を、CDN ホストのフレームワークと最小の AI 出力で同時に解決します。

三つの層

bento は単一の framework ではなく、責任範囲の違う三つの層の重ね合わせです。 どれか一つでも欠けると、出力は AI 臭くなるか、見た目だけ綺麗になります。

① 視覚

bento.css と bento.js が 76ch のリーディングカラム、1.65 の行間、17px の本文、 callout・card・chart・mermaid を提供。

AI のクラス選択だけで成立

② 文

writing-style.md が em-dash・"delve"・三つ並べ・「単なる○○ではなく」など AI-tell を 30 種類以上カタログ化。

書きながら参照する規律

③ 文書

readability.md が BLUF / Pyramid Principle、 段落設計、見出し階層、コンポーネント選択の閾値を定義。

書く前に決める骨格

層① 視覚: フレームワーク

視覚層の責任は「AI が貧弱な CSS を書かない」こと。 HTML を <link> と <script> 2 行に 繋ぐだけで、全コンポーネントが使えるようになります。 タイポグラフィ・配色・余白の判断は AI ではなくフレームワークが下します。

層② 文: writing-style.md

一行の原則

立場を取る。具体的に書く。リズムを揺らす。
AI 文章のテルは、ほぼ全部この三つのどれかをサボった結果です。

語彙リストは便利ですが、根は三つの「コミットしない」習慣です。 断定を避ける、抽象に逃げる、同じ拍子で続ける。 禁止語を一つ削っても、この習慣が残っていると別の禁止語が代わりに出てきます。

✗ AI シンプルで、軽量で、わかりやすい設計です。
✓ Human 設計は軽い。プラグイン一つで全部組み替えられます。
✗ AI これは単なるツールではなく、思考の枠組みです。
✓ Human これは思考の枠組みです。
flagged words 30+ 英語 + 日本語
em-dash 予算 0–1 最大の指紋
セルフチェック 11 書き終わる前

詳細と置き換え辞書は writing-style.html に視覚化されています。

層③ 文書: readability.md

skim 率 ~70% word-by-word では読まれない
判断時間 5–7s 読む価値があるかの初期判定

読者の 7 割は読まずに skim します。 だから結論を先に置き、見出しを「中身の縮図」として並べ、 各章の冒頭に視覚要素を一つ入れる。これだけで残り 3 割の精読読者にも届きます。

flowchart TB C[結論: 18%下落] C --> R1[要因 1
UI 簡略化] C --> R2[要因 2
導線変更] C --> R3[要因 3
本人確認追加] R1 --> E1[A/B 結果] R2 --> E2[ヒートマップ] R3 --> E3[フォーム計測]

Pyramid Principle (Minto, 1969) の骨組み。 上から下へ「結論 → 根拠 → 証拠」と読める設計になっていれば、 skimmer は上層 1 層で意思決定でき、精読者は下層まで辿れます。

✗ AI: 5 段落エッセイ 導入 → ポイント1 → ポイント2 → ポイント3 → まとめ。 均一な段落、最後に「課題はあるが今後に期待」。
✓ Pyramid 結論 1 段落 → 根拠 3 章 (不揃いの長さ) → 各章に証拠と例。 最後はもう書かない。

階層と段落設計の詳細、コンポーネント選択の閾値 （paragraph と <ul> の境目、何個から card grid にするか）は readability.md に表形式でまとまっています。

層を越えて: 双方向 HTML

Thariq の記事 "The Unreasonable Effectiveness of HTML" が指摘する HTML の最強の用途は Custom Editing Interface です。 bento は v0.1 でこの用途のためのプリミティブを揃えました。

入力コントロール

<input>, <select>, <textarea>, <fieldset> がクラスなしで自動スタイル。 .bento-field でラベル＋コントロールを束ねる。

レイアウト

.bento-sidebar で非対称 narrow+wide。 data-side と data-ratio で エディタ・パレット・ナビ + 本体を組める。

SVG / 描画

.bento-illust で SVG を包めば、 currentColor が --bento-accent を 継承してテーマに自動追随。

ループを閉じる

<button class="bento-btn bento-copy" data-copy-from="#payload">。 編集結果をクリップボードに戻して、別の Claude セッションに貼り直せる。

実例は playground.html の callout デザイナーで。フォーム入力がライブプレビューに反映され、 最後に「Copy HTML」で .bento-callout マークアップを取り出せます。

出力を閉じる前のチェック

writing-style.md と readability.md のチェックを統合した最小セット。 3 項目以上失敗していたら書き直しの合図です。

  1. 結論が先

    最初の 1–2 段落に bottom line が出ているか。

  2. 見出しの parallel

    <h2> 兄弟が同じ文法形か。スキマー読者がそこだけで筋を辿れるか。

  3. 各章に視覚要素

    callout / card / stat / chart / compare / mermaid のどれかが <h2> ごとにあるか。

  4. em-dash

    0 個、または明確な意図のある 1 個まで。

  5. 禁止語彙

    delve / leverage / pivotal / robust / seamless が無いか。日本語側は「まず・次に・そのため」のデフォルト位置。

  6. 否定対比

    not just X, but Y / 「単なる○○ではなく」を使っていないか。

  7. 具体性

    固有名詞・数字・日付が 1 ページに最低 3 個。

  8. 段落の長さ

    多くは 1–4 文。長い段落が連続していないか。

  9. 箇条書きの正体

    本当にリスト構造か。3 個未満なら一文、7 個超なら分割。

  10. 立場

    誰かが反論できる主張が、文書中に最低一つあるか。
